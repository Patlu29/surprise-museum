# 0007: Waypoint navigation and 2D collision, without a physics engine or navmesh

## Status
Accepted (27/10/2026)

## Context
Characters must not pass through walls or leave the museum (FR-34). The Guide must walk around walls without getting stuck (FR-31). The layout is generated by our own code from axis-aligned rooms, so its geometry is fully known. The reference phone must hold 30 FPS (NFR-1), and the first view should stay small (NFR-4). Options: Rapier physics (about 1.5 MB WASM), a navmesh library (Recast WASM or `three-pathfinding` with an authored mesh), or a waypoint graph generated with the layout.

## Decision
- Collision: circles (r = 0.3 m) against axis-aligned boxes, resolved by pushing out along the shortest axis, so characters slide along walls. The Visitor and Guide do not collide (A-18).
- Navigation: a waypoint graph produced by `generateLayout` (centreline nodes, doorways, photo standing spots, spawn, finale), A* with string-pulling, and line-of-sight shortcuts.
- Stuck detection and relocation as in FR-31.

## Consequences
- No extra dependency or WASM; the cost is well under a millisecond per frame.
- Works only because the layout is ours and axis-aligned. Free-form or authored layouts (themes in Release 2 with irregular rooms) would need a navmesh; the navigation API is kept behind `src/domain/navigation` so it can change.
